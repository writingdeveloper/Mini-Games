## 1. 문제 / 동기

현재 게임은 "감자튀김을 좌우로 옮겨 떨어뜨리기"가 전부다. 코드상:
- `drop()`은 속도 없이 놓기만 함 → 손을 떼면 플레이어는 관전자 (`Session.js:57`).
- 모든 감자튀김이 `z=0`, Z축 회전 하나만 → **타워가 사실상 2D 평면**. 스펙이 약속한 "통나무집 교차"가 불가능.
- 씬에 캐릭터/집게가 없음 — 스펙 §3의 "claw/hand above the tray"가 미구현.

**목표:** ① 조작 자유도/손맛을 크게 높이고, ② "감자튀김을 직접 올리는 3D 캐릭터(손)"를 구현하고, ③ 한 줄이 아니라 **입체로** 쌓이게 한다. 세 가지를 **하나의 메커닉**으로 통합한다.

## 2. 포지셔닝 (확정)

**균형(Balanced).** 교차/3D 깊이의 전략성은 살리되 컨트롤은 정리한다. 기본 코어만으로도 재밌고, 고급 옵션과 모바일은 단순 매핑. *깊이와 접근성 둘 다.*

## 3. 핵심 메커닉 (프로토 검증 완료)

플레이어는 떠 있는 감자튀김 대신 **셰프의 관절 팔/손을 조종**해 집어 올려 얹는다.

- **팔 = 2본 IK** (어깨→팔꿈치→손목). 손목 타깃을 조준점에 맞춰 자연스럽게 뻗음 (`hand-proto.js` `solveElbow`).
- **손 = 자연 비율 툰 손** (손바닥+4손가락+엄지, `setGrip(0..1)`로 쥐고 폄). 형태·움직임은 진짜 손, 마감은 게임과 같은 툰+굵은 외곽선.
- **모멘텀 = 실력:** 놓는 순간 손의 최근 속도가 감자튀김에 전달됨. 빠르게 움직이다 놓으면 휙 날아가고, 멈춰서 놓으면 살포시. *"그냥 떨어뜨리기"의 정반대.*
- **초보 보정(assist):** 켜면 전달 속도를 줄여 정밀 배치 쉬움.

## 4. 입체 배치 + 3D 회전 (확정)

- **X·Z 평면 이동:** 손이 트레이 위를 좌우(X) + 앞뒤(Z, 깊이)로 이동 → 한 줄 탈출, 면(面)으로 쌓임.
- **Yaw 회전 (수평):** 감자튀김 긴 축을 수평으로 돌림 → **교차(crisscross)의 핵심**. 가로↔세로 90° 전환으로 우물정(井)/통나무집.
- **Tilt 기울이기 (pitch) — 고급:** 앞뒤로 기울여 비스듬히 얹기. 기본 조작엔 없고 고급/데스크톱 옵션.
- 물리 충돌체는 박스 그대로(`makeFryBody`), 비주얼만 3D — 시각/물리 분리 유지.

## 5. 카메라 (확정)

- **팔이 카메라를 따라 회전:** 어깨 앵커·조작 방향·감자튀김 회전 기준이 모두 카메라 방위(azimuth)를 공유 → 어느 각도에서 봐도 팔이 화면 같은 쪽에서 들어옴 (`hand-proto.js`의 `azi` 적용, 검증됨).
- **기본 = 약한 자동 궤도 또는 스마트 앵글**(깊이가 보이는 3/4 뷰). **수동 궤도는 보조**(데스크톱 `[ ]`, 모바일 "시점" 버튼). "정면 리셋" 제공.
- 카메라 궤도 중 손 움직임은 모멘텀으로 치지 않음(검증됨).

## 6. 비주얼 (확정)

- **손/팔:** 코드로 만든 자연 비율 툰 손(검증). *향후* 같은 IK 리그 위에 더 정교한 손 메시로 교체 가능(업그레이드 경로 유지).
- **감자튀김:** 사용자가 생성한 참고 이미지 **기반**으로 재현한 입체 메시 — `RoundedBoxGeometry` + 살짝 휜(banana) + 끝 테이퍼, 정점색(진한 황금 몸통·바삭한 윗면·얼룩·연한 잘린 끝), 툰+외곽선. 사진 텍스처 직접 입히기는 **하지 않음**(360° 카메라에서 어색 + 툰과 충돌).
  - **변형(variety) 필수:** 모든 감자튀김이 같으면 "윷"처럼 단조로움 → **여러 variant**(길이·굵기·휨·표면 요철·색 톤·바삭함 제각각)를 미리 생성하고 무작위로 골라 더미가 자연스럽게. (프로토는 7종, 안정 LCG로 로드마다 동일.)
  - 색 톤·변형 수는 사진 대비 미세조정 가능.
- 기존 밝은 카툰 정체성(트레이 빨강·배경·외곽선) 유지 — 손/감자튀김 모두 한 세계.

## 7. 컨트롤 스킴 (균형)

**기본 코어 (모두 공통, 이것만으로 교차 플레이 충분)**
- 손 위치: 트레이 위 X·Z 이동
- Yaw 회전
- 놓기 (모멘텀 적용)
- 초보 보정 토글

**고급 (데스크톱/옵션)**
- Tilt(기울이기), 높이 미세조정, 수동 카메라 궤도

**데스크톱 키 (프로토 기준):** `←→` X · `↑↓` Z · `Q/E` yaw · `Z/X` tilt(고급) · `W/S` 높이(고급) · `[ ]` 카메라(고급) · `Space` 놓기 · `A` 보정 · `R` 리셋. 마우스: 드래그=위치, 탭=놓기.

**모바일 (코어만):** 드래그=트레이 위 위치(X·Z) · 회전 버튼=yaw · 탭=놓기 · "시점" 버튼=카메라. tilt·수동 높이는 모바일 기본 제외(또는 고급 토글). *Phase 3a 기존 터치 컨트롤 재작성 — 통합의 최대 작업.*

## 8. 게임 규칙 / 점수 (대부분 유지, 가중치 재조정)

- **목표 불변:** 제한 시간(~90s) 내 가장 높은 **안정** 타워.
- **전략축(신규 핵심):** 교차=안정·느림 ↔ 수직=고득점·불안정. 3D 회전이 이 선택을 만든다.
- **점수:** 높이(주) + 안정 보너스(정착) + 콤보(연속 안정 → 멀티 사보타지 충전) + 시간 보너스. *(후순위 옵션: 교차/오버행 스타일 보너스.)*
- **도전/긴장:** 타이머 유지 + 모멘텀 리스크. *(옵션 검토: 높이 올라갈수록 흔들림↑ 또는 주기적 약풍.)*
- **붕괴:** 기존 로직 유지(플레이 볼륨 이탈/트레이 라인 아래).

## 9. 기존 게임 통합

**재작성 대상**
- `play/Session.js`: 스폰/드롭/조작 → 손 리그 + 3D 배치 + 모멘텀. (round/scoring/combo/collapse 순수 로직은 재사용·확장.)
- `core/Input.js`: 새 컨트롤 스킴(데스크톱 + 모바일).
- `render/`: 신규 `HandRig`(IK 셰프 손) + 카메라 컨트롤러; `fryMesh.js`를 사진 기반 입체 감자튀김으로 갱신.

**그대로 유지**
- 멀티플레이(독립 타워·`{height,count}` 동기화) — 높이는 여전히 높이.
- 사보타지(강풍/기름/갈매기) — 물리 바디에 그대로 작용.
- 오디오(쥐기/놓기 사운드 추가), 콤보/라운드/점수 순수 로직.

**프로토 → 프로덕션:** 검증된 `hand-proto.js`의 손 리그·모멘텀·3D 배치·카메라 연동·감자튀김 메시를 `src/` 모듈로 정리해 이식.

## 10. 에셋 계획

- **손:** 절차적 툰 손(현재, 검증) → 필요 시 sculpted/rigged glTF로 교체(동일 IK 리그). CC0 또는 사용자 생성.
- **감자튀김:** 정점색 둥근 툰 메시(현재, 검증). 최종 색 톤 확정 필요.
- 빌드프리 유지(three importmap + `three/addons` GLTFLoader 이미 사용 가능).

## 11. 단계 로드맵

- **Phase A — 솔로 코어 이식:** 손+모멘텀+3D 배치(코어 컨트롤) + 사진 기반 감자튀김 + 자동궤도 카메라를 솔로에 통합. 타이머/점수/붕괴 유지. 게이트(unit/lint/type) + 플레이 검증.
- **Phase B — 모바일 + 고급 + 점수:** 터치 컨트롤 재작성, tilt·수동 카메라(고급), 점수 가중치/교차 보너스, 도전 장치(흔들림/약풍) 검토.
- **Phase C — 멀티/사보타지 재검증 + 폴리시:** MP·사보타지 동작 확인, 손 메시 업그레이드·감자튀김 색 확정·오디오 큐.

## 12. 테스트

- **Unit(Vitest):** scoring/combo/round 등 순수 로직 유지·확장. 새 순수 로직(있다면) 추가.
- **e2e(Playwright):** 캔버스 0 에러 · 감자튀김 배치/교차 가능 · 타임드 라운드 완료 · (MP) 상호 높이 동기화. (프로토 검증 스크립트 패턴 재사용.)
- Lint + type-check 그린.

## 13. 미해결 / 후속

- 모멘텀 민감도·보정 동작 수치 튜닝.
- 도전 장치(흔들림/약풍) 채택 여부.
- 손 메시 업그레이드(절차적 vs glTF) 시점.
- 감자튀김 최종 색 톤(사진 대비).
- 모바일에서 yaw 외 회전(tilt) 제공 여부.
